---
title: 'Override a price on an order'
description: 'Send `discountClaimReason` and `staffContactName` whenever you set `priceOverRidden` in the Agent / Reseller API'
---

When you set `priceOverRidden` to `true` on a product line, you must also send `discountClaimReason` and `staffContactName` on that same line.

Send all three together, or none of them.

## The three fields that travel together

```json
{
  "products": [
    {
      "productPricesDetailsId": 11476906,
      "qty": 1,
      "priceOverRidden": true,
      "discountClaimReason": "Customer finishing tour 2 days early as per agreement with supplier contact Jane Smith on 10-Mar-2026",
      "staffContactName": "Jane Smith"
    }
  ]
}
```

This shows only the fields this rule concerns. For every field a product line accepts, see [Submit an Order](/api-reference/agent-reseller-api/order-placement/submit-an-order).

The same rule applies to the product line in `POST /apiv1/validateCart`.

## What happens if you omit them

`POST /apiv1/order` fails with **HTTP 500** and a response body that names no field:

```json
{
  "type": "https://tools.ietf.org/html/rfc2616#section-10",
  "title": "An error occurred",
  "status": 500,
  "detail": "Internal Server Error"
}
```

The underlying error is `Price Override entered for '<product name>' but either no Discount Reason or Staff Contact Name Entered`. It is not returned in the response. If you see a 500 from `POST /apiv1/order` with no detail, check these two fields first.

`POST /apiv1/validateCart` accepts the same product line without them and reports the cart as valid. A cart that validates cleanly can still fail at order, so validating is not a check that an overridden line is complete.

## Notes

- A booking reference obtained from `POST /apiv1/bookingreference` is spent on a failed order attempt. Retrying means requesting a new one.
- Send `priceOverRidden` only on the lines you are overriding. Lines sent without it are unaffected by this requirement.
